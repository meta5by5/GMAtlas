# Saga Atlas Design Constitution

# Final Summary --- The Unified Vision

## Why Saga Atlas Exists

Saga Atlas is not intended to become another campaign manager.

It is intended to become a **Campaign Operating System**.

A campaign is treated as a living system whose most valuable assets are
not character sheets or random tables, but context, continuity,
relationships, discoveries, and history.

The software exists to protect the Game Master's attention.

------------------------------------------------------------------------

# The Core Philosophy

Every design decision should optimize for **Frictionless Empowerment**:

-   Reduce cognitive load.
-   Preserve campaign continuity.
-   Increase creative agency.
-   Minimize navigation.
-   Surface relevant information automatically.
-   Keep the Game Master in control.

Whenever two solutions are technically equivalent, choose the one that
requires fewer decisions while preserving more story context.

------------------------------------------------------------------------

# The Architectural Vision

Everything centers on Mission Control.

Mission Control is not a dashboard.

Mission Control **is the application**.

Everything else exists to support it:

-   Story Engines
-   Context Graph
-   Storage Kernel
-   Decision Engine
-   Activity Engine
-   Campaign Intelligence
-   Knowledge Graph
-   Drawers
-   Plugins

The architecture is layered so that presentation, domain logic,
persistence, and integrations remain independent.

------------------------------------------------------------------------

# The Mental Model

Saga Atlas should mirror how Game Masters naturally think.

Observe

↓

Understand

↓

Choose

↓

Resolve

↓

Remember

↓

Continue Story

The software should adapt to this workflow rather than forcing users
into feature-oriented navigation.

------------------------------------------------------------------------

# The Living Campaign

Campaigns evolve.

NPCs change.

Factions pursue goals.

Threads converge.

Consequences accumulate.

Time passes.

Saga Atlas remembers these changes and uses them to produce contextual
recommendations without ever dictating narrative outcomes.

------------------------------------------------------------------------

# Story Before Mechanics

Rules systems are interchangeable.

Story is permanent.

Rules become **Rules Lenses**.

Activities remain system-neutral.

Campaign continuity survives changes in mechanics.

------------------------------------------------------------------------

# Relationships Create Meaning

Information gains value through relationships.

The Context Graph is therefore the heart of the platform.

The graph connects:

-   Characters
-   Groups
-   Missions
-   Locations
-   Threads
-   Discoveries
-   Journal entries
-   PDFs
-   Rules
-   Oracles

The graph becomes both memory and navigation.

------------------------------------------------------------------------

# The Co‑Pilot

The Co‑Pilot is an advisor.

Never a narrator.

It observes context, explains recommendations, highlights forgotten
opportunities, and proposes useful next actions.

Authority always remains with the Game Master.

------------------------------------------------------------------------

# Long-Term Success

Saga Atlas succeeds when:

-   preparation becomes shorter,
-   campaigns become easier to resume,
-   continuity improves,
-   searching becomes rare,
-   recommendations become trustworthy,
-   the software quietly disappears.

Players remember the adventure.

Game Masters remember the story.

Nobody remembers the software.

------------------------------------------------------------------------

# Final Constitutional Principle

Every future implementation should answer one question:

**Does this help Game Masters tell richer stories with less effort while
preserving complete creative ownership?**

If the answer is yes, it belongs in Saga Atlas.

If not, redesign it.

------------------------------------------------------------------------

*End of the Saga Atlas Design Constitution (Initial Edition).*
